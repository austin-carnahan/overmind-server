# Browser dictation versus Talk

When a user wants speech-to-text in the browser Chat composer without spoken replies:

1. Distinguish the two gestures on the composer microphone: a normal click starts realtime Talk (with voice responses); **press and hold** invokes dictation into the text draft. Open the small caret beside the microphone and check **Hold to dictate**. In the inspected 2026.9.6 UI this preference defaults on unless explicitly turned off. Finish the dictation, review the draft, and send it as an ordinary text message.
2. If holding does not dictate, inspect the microphone picker for dictation readiness and selected input. Talk readiness does not prove dictation readiness: browser Talk can transcribe within its realtime provider session while draft dictation needs a separately registered streaming transcription provider. Do not redirect to system dictation or claim browser dictation is absent before checking this path.
3. If the picker says **no transcription provider is configured**, inspect `talk.catalog.transcription` readiness, the enabled provider plugins, credential metadata, and existing config before changing anything. In OpenClaw 2026.9.6, the Gateway relay uses the Voice Call `streaming` provider configuration until a dedicated Talk transcription config surface ships (`docs/nodes/talk.md`; `docs/plugins/voice-call/realtime-and-streaming.md`). Supported bundled realtime transcription providers are Deepgram, ElevenLabs, Mistral, OpenAI, and xAI. Do not infer that an OpenAI OAuth profile usable for realtime Talk is an API credential for OpenAI streaming transcription; verify provider eligibility. If none is eligible, explain the blocker and obtain explicit spend approval before adding a usage-billed service or credential; use masked setup, never chat for secrets.
4. If the user wants **local Whisper without API billing**, distinguish OpenClaw's local `whisper-cli`/`sherpa-onnx-offline` fallback for **audio attachments** (`docs/nodes/audio.md`) from the browser's **streaming** dictation provider. Installing the CLI alone does not make the picker ready. Check for an existing maintained realtime-transcription plugin before proposing custom integration; the external Faster-Whisper browser-dictation plugin found for 2026.9.6 explicitly labels itself experimental and not production-qualified, with CUDA/medium defaults unsuitable for this Raspberry Pi 4. Treat CPU-small-model latency and real microphone quality as unverified until benchmarked. Do not imply existing OpenAI OAuth access needs or provides paid API billing without checking the particular transcription path.
5. Verify readiness changes in the browser picker and a hold-to-dictate test: speech becomes an editable composer draft and the sent message receives a text reply without entering Talk. If the control is missing, inspect the deployed version; report observed status rather than guessing a switch.

The installed browser UI implementation was inspected in OpenClaw 2026.9.6: its composer microphone picker exposes **Hold to dictate**, and the button branches between hold-dictation and ordinary Talk. The browser Chat docs describe the composer Talk control and dictation microphone recovery at docs/web/control-ui/chat.md. Native iOS/Android microphone instructions are not substitutes for browser behavior.
