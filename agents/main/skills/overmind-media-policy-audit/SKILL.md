# Overmind media policy and cleanup

Use for torrent cleanup, retention eligibility, and blocked-import visibility. Keep canonical intent, live runtime, persisted settings, and observed effects distinct. An audit is read-only; only apply a requested policy change after inspecting its immediate effects.

1. Read the relevant /opt/overmind/services/{transmission,sonarr,radarr,maintainerr} docs/config and /opt/overmind/services/maintainerr/retention-policy-v1.json. Treat example settings and status labels as intent, not proof of deployment. Check live containers with `sudo docker ps` and inspect actual mounts with read-only `sudo docker inspect`; use `sudo /usr/local/sbin/overmind-svc status <container>` for service readiness. Do not infer that other Docker or sudo operations are permitted. Use loopback application APIs for read-only state.
2. **Torrent branch:** inspect Transmission's deployed `/config/settings.json` through the mount reported by Docker, selecting only seed/ratio/queue/watch/cleanup keys; never print RPC credentials. On the migrated host, `/config` is a directory bind at `/var/lib/overmind/transmission/config`, with resume/torrent state alongside settings. Older single-file binds blocked Transmission's atomic save and left state in an anonymous volume; check mount topology before any durable policy change. The file may omit runtime defaults. For each Arr app, read its local `config.xml` API key in process memory only and query `/api/v3/config/downloadclient`, `/api/v3/downloadclient`, `/api/v3/queue`, and bounded `/api/v3/history`. Report completed-download handling, top-level `removeCompletedDownloads`/`removeFailedDownloads`, `autoRedownloadFailed`, client enabled/category, and relevant import warnings; never print raw client JSON or credentials.
3. Do **not** equate 100% downloaded or Arr's remove-completed toggle with removal eligibility. Query Transmission's read-only RPC `session-get` for global ratio/idle limits and `torrent-get` for per-torrent limit modes, status, and `isFinished`. If RPC needs credentials, take `USER`/`PASS` from the deployed Transmission `.env` or container environment in process memory only, and use HTTP Basic auth; compare Arr client credentials without printing them. The Arr API may mask passwords. On this linuxserver image, missing `USER` or `PASS` disables RPC authentication even if `settings.json` says otherwise; verify an unauthenticated request is rejected and an authenticated request succeeds. A torrent inheriting disabled global limits can seed indefinitely with `percentDone=1` and `isFinished=false` despite Arr cleanup enabled. Check import success independently: a queue item with `importPending` and a file-type warning is not a successfully imported job. Attribute a re-add only after correlating that item's Arr history/client timestamps; automatic retry/monitoring alone is not proof of its cause.
4. **Requested seed-policy change:** Before runtime mutation, verify the `/config` directory mount, persistence/restart path, and immediate impact: inspect live ratios and per-torrent modes, Arr import history, and queue warnings. If the path is still a single-file bind or cannot persist, report the blocker before applying a transient-only policy. Already-over-threshold imported jobs may stop and be removed immediately; a blocked import is not safe to treat as successful cleanup. Idle-seeding time is inactivity without upload, not a wall-clock cap since completion. Read live RPC field names/version: the inspected Transmission 4.1.3 legacy RPC accepts `seedRatioLimit`, `seedRatioLimited`, `idle-seeding-limit`, and `idle-seeding-limit-enabled` (24 hours = 1440 minutes), while persisted JSON uses `ratio-limit`/`ratio-limit-enabled` plus the idle keys. Use the service RPC/WebUI for a running daemon; edit its config file only while stopped. After `session-set`, verify runtime read-back, `isFinished`, Arr queue/history, and torrent count. Transmission writes settings on clean shutdown: for durability, use the documented `overmind-svc` restart path when authorized, then check both persisted file and RPC after restart, as well as resume/torrent state. Reflect the policy in canonical example/docs; do not claim durability solely from runtime read-back.
5. **Retention branch:** query loopback Maintainerr `/api/rules` (and `/api/rules/constants` to map property IDs). Inspect group and collection `isActive`, `deleteAfterDays`, `arrAction`, and each row's parsed `ruleJson` plus row activation. Compare to the canonical policy; the repo's apply script **without** `--apply` only prints a plan and does not prove equivalence. Do not emit raw settings responses, which can contain credentials.
6. For a named title, check **Jellyfin last watch across users**, favorite state, and Arr import/file status, not just download or library-add date. The 30-day inactivity condition starts at last viewing and the 14-day grace starts only after a title enters Leaving Soon; a later view or changed predicate can remove it from the collection. Inspect Maintainerr's `collection_log` and `collection_media` read-only (SQLite `mode=ro`) and job schedules to distinguish added, removed-from-collection, and actually deleted. An active rule, an empty collection, or a handled count of zero does not by itself establish no evaluation or no prior entries.
7. **Blocked-import visibility:** Inspect existing Arr Connect destinations/events and the live Seerr/Jellyfin deployment before proposing an alert route. A queue `importPending` warning is not necessarily emitted by native lifecycle/health events. Research maintained options first: Notifiarr documents stuck-queue Discord alerts but adds a local client plus hosted account/Discord; Cleanuparr handles `.zipx` failed imports and notifications but is a separate cleanup service with removal authority. Explain dependencies and risks; if none fits the requested scope, leave alerting alone rather than defaulting to a custom script/timer.
8. Report observed runtime, persisted configuration, actual removal/deletion evidence, and unresolved causality. State what changed, or explicitly that an audit made no changes.

Source paths and ports are local to Overmind; verify against current compose/config before use. In this stack, Sonarr/Radarr use 8989/7878 and Maintainerr 6246 on loopback; credentials remain in process memory.
