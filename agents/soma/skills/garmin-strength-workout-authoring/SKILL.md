# Garmin strength workout authoring

1. Confirm sequence, rounds, optional steps, completion condition per step, and whether Austin wants a library workout, calendar entry, or watch delivery. Check `getWorkouts` before creating a duplicate. Keep skippable skills outside a mandatory circuit, clarify unilateral rep counting and substitutions, and put progression cues in descriptions/notes. Scheduling and Send to Device are separate; do not schedule a library-only workout.
2. Select the simplest faithful route. `createStrengthWorkout` creates rep-based steps, each exercise separately repeated when sets > 1; use it only for that model. Garmin Connect itself supports sets with multiple ordered children and per-step reps, time, or lap-button completion. For a multi-exercise circuit, holds, manual completion, or unusual sequencing, use `uploadWorkout` rather than flattening the workout or defaulting to UI guidance. If raw cannot express a requested detail, use the authorized Connect builder: Add Sets groups ordered child steps; its per-step controls include exercise, weight, target, notes, and audio note.
3. For raw authoring, consult the `garmin-workouts` skill for the validated JSON, condition IDs, targets, and catalog resolution. Arrange workout → segment → executable steps/repeat groups. A circuit is one RepeatGroupDTO holding the ordered movements with numberOfIterations and endCondition {conditionTypeId: 7, conditionTypeKey: "iterations"} plus matching endConditionValue; the MCP template omits that essential condition and can silently corrupt the repeat count. Resolve exact category/exerciseName pairs from Garmin's catalog instead of inventing identifiers; choose endCondition independently of intensity targetType. Preserve preferred movement wording in description.
4. Upload, then read back with `getWorkoutById` and compare sport, hierarchy, repeat count, child order, identifiers, descriptions, and conditions/values against intent. Check targets only where exposed; a successful upload alone is insufficient, and the curated read-back can omit no-target fields and a lap-button value. Report what remains unverified (including watch execution). Schedule only if requested after validation; watch delivery still needs a separate Send to Device action.
