# Garmin run/walk workout authoring

1. Read the relevant existing workout with `getWorkouts` and `getWorkoutById` before adapting its intervals; check for a duplicate name. Confirm run/walk seconds, repetitions, warm-up/cool-down, whether effort is free or HR-targeted, and whether the user wants only a library workout or a scheduled date. For a preview request, do not upload.
2. Choose the interface by intent: `createWalkRunWorkout` builds a timed repeat but defaults to **Z3 HR target**. Do not silently impose that target on an easy conversational-jog workout. For free-effort intervals, use `uploadWorkout` with each ExecutableStepDTO's `targetType: {workoutTargetTypeId: 1, workoutTargetTypeKey: "no.target"}`. Consult the `garmin-workouts` skill for the raw DTO model and validation rules.
3. Raw running sport is `{sportTypeId: 1, sportTypeKey: "running"}`. Put timed warm-up (stepType ID 1), a RepeatGroupDTO (ID 6) containing timed run interval (ID 3) and walk recovery (ID 4), then timed cool-down (ID 2) in one segment. Timed steps use `endCondition: {conditionTypeId: 2, conditionTypeKey: "time"}` with seconds. The repeat group needs `numberOfIterations`, `endCondition: {conditionTypeId: 7, conditionTypeKey: "iterations"}`, and matching `endConditionValue`; omitting ID 7 can silently corrupt the repeat count. Describe easy effort in the run step rather than prescribing a pace or HR alert without a reason.
4. After upload, read `getWorkoutById` and verify sport, warm-up/cool-down seconds, repeat count, ordered run/recovery seconds and step types, descriptions, and timed conditions. Garmin's curated read-back omits `no.target`, so the absence of watch HR alerts is not verified; `estimated_duration_seconds` can also differ from summing the displayed steps, so report interval structure rather than inferring watch behavior from metadata. Library upload does not schedule or send to a watch. Schedule only if requested; Send to Device remains a separate manual action, and watch execution is unverified until tested.
