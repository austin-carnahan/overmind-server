# Composio on Overmind

Verified 2026-11-01. Update this file as you learn real behavior.

## Setup

- CLI `composio` 0.6.0, installed for the `openclaw` user (`~/.composio`, on PATH via `~/.npm-global/bin`).
- Logged in as the user's own Composio account (a "For You" human login, not an agent account). Check with `composio whoami`.
- Skill: `skills/composio-cli/` in this workspace, generated by `composio setup skill` from the same CLI release.

## Connections

`composio connections list` shows: Pinterest, Bright Data, Gmail, Google Calendar (all active), Google Sheets (expired).

## Pinterest

- `PINTEREST_LIST_BOARDS` works, and returns secret boards too. Secret boards are the user's private taste; don't share their names or contents outside the conversation.
- Pinterest app limits: trial-access apps can't create Pins, and production Pin writes need Pinterest Standard access. Expect writes to fail until proven otherwise.

## Web search: not through Composio

Use `web_search` (Brave) and `web_fetch` for web research; they cost nothing per call. See this skill's `SKILL.md`.

- Composio's own search toolkit is switched off on purpose (`COMPOSIO_SEARCH_WEB` fails with "Toolkit 'composio_search' is disabled for this session"). Don't ask to enable it: it would spend Composio quota on what Brave already does.

## Finding Pins by keyword (free)

1. `web_search` for `<topic> site:pinterest.com/pin`. Verified: 8 real Pin URLs for "japandi bedroom".
2. `web_fetch` (or `curl`) the Pin page. Pinterest serves it as plain HTML, with no browser needed. Its meta tags give:
   - `og:image`: the image, `https://i.pinimg.com/736x/…jpg`;
   - `og:title` and `og:description`;
   - `og:see_also`: the original source page, often worth following;
   - `"saves"` and `"repin_count"` in the page data: a popularity signal.
3. Download the images you want into the project, then look at them with `view_image`.

Keep it to the handful of Pins a brief needs. Pinterest's robots.txt disallows unlisted bots (`User-agent: * / Disallow: /`); this is user-directed lookup, not crawling.

## Bright Data (paid: ask first)

Bright Data bills per returned record or per request. Use it only with the user's approval, for something the free tools can't reach, and always cap results (`limit_per_input`, `num_of_posts`).

- No zones (now called "API configurations" or "Proxies" in Bright Data) exist yet. `BRIGHTDATA_LIST_WEB_UNLOCKER_ZONES` returns none, so `BRIGHTDATA_SERP_SEARCH` and the unlocker don't work. Creating one (`BRIGHTDATA_CREATE_SAFE_ZONE`) may cost money: the user decides.
- The dataset scrapers don't need a zone; they use the connected API key.
- Tags are not a cost signal: `BRIGHTDATA_FILTER_DATASET` is tagged `readOnlyHint` but creates a billable snapshot.
- Pinterest datasets:
  - Posts (`gd_lk0sjs4d21kdr7cnlv`) discovers only by profile URL. Asking it for `discover_by=keyword` returns "Incorrect discovery collector id Available types: profile_url". It can also collect given Pin URLs (`collect_by_url`).
  - Profiles (`gd_lk0zv93c2m9qdph46z`) discovers by keyword: `BRIGHTDATA_SCRAPE_PINTEREST_PROFILES` with `mode: discover_by_keyword`.

## CLI behavior

- `composio proxy <url> -t brightdata` calls Bright Data's own API with the connected key, for anything the tools don't cover. It exits 0 even when the provider returns an error, so read the body.
- Large results are written to a file under `/tmp/composio/` and the command prints its path. `/tmp` on Overmind is RAM: delete those files when you're done.
